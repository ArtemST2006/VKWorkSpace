# msgfmt

Часть 1 тестового задания: библиотека и команда на C++17 для преобразования подмножества Markdown в чистый текст и диапазоны форматирования. Во время сборки и запуска нужна только стандартная библиотека C++.

## Сборка и тесты

Из корня репозитория:

```bash
cmake -S msgfmt -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure
```

Для проверки адресов и неопределённого поведения можно собрать отдельный каталог с `-fsanitize=address,undefined`:

```bash
cmake -S msgfmt -B build-sanitize -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_CXX_FLAGS="-fsanitize=address,undefined -fno-omit-frame-pointer" \
  -DCMAKE_EXE_LINKER_FLAGS="-fsanitize=address,undefined"
cmake --build build-sanitize
ctest --test-dir build-sanitize --output-on-failure
```

Цель `msgfmt_lib` содержит библиотеку; `msgfmt` — исполняемую команду. CTest проверяет библиотеку на контрольных примерах приложения А, дополнительные случаи вложенности, экранирование, UTF-8 и CLI.

## Использование

Команда без аргументов читает весь stdin как UTF-8 и выводит один JSON-объект:

```bash
printf 'Привет, **мир**!' | build/msgfmt
# {"text":"Привет, мир!","ranges":[{"style":"bold","offset":8,"length":3,"url":""}]}

printf '2 * 3' | build/msgfmt escape
# 2 \* 3
```

При некорректном UTF-8 обе команды выводят `{"error":"invalid_utf8"}` и завершаются с кодом `2`. Позиции и длины диапазонов измеряются в кодовых единицах UTF-16; например, `🚀` занимает две единицы. Библиотечный API объявлен в `include/msgfmt/msgfmt.hpp`; `parse` и `escape` при ошибке кодировки бросают `InvalidUtf8`.

## Принятые решения и ограничения

- Парсер обрабатывает маркеры слева направо, а результат собирает после определения их пар: так можно вывести незакрытую конструкцию буквально, включая разметку и экранирование внутри неё. Вложенный незакрытый стиль, встретив закрытие внешнего, тоже становится буквальным текстом.
- Внутри `code` не действуют разметка и обратный слеш. Текст ссылки не может содержать `]`, в том числе экранированную; URL не может быть пустым, содержать пробельные символы или `)`.
- Проверка границ слова использует фиксированные таблицы Unicode 15.0.0: категории букв `L` и десятичных цифр `Nd`. Пробелы определяются свойством Unicode `White_Space`. Таблицы встроены в исходники, поэтому поведение не зависит от системной локали.
- Весь stdin буферизуется для проверки UTF-8 до вывода. Символы, добавленные в Unicode после 15.0.0, не распознаются как буквы или пробелы до обновления таблицы.
